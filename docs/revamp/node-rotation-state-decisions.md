## API and state ownership

New Repeater module repeater/glass/rotation_state.py exposes prepare_rotation(credentials, *, store_dir) -> dict. credentials is the already loaded/validated enrollment bundle, containing device_id/base_url/operational_token/private_key/client_cert/ca_cert/cert_serial/expires_at/pubkey. Validate again with enrollment helpers before creating state. This first helper accepts only currently valid credentials; expired-certificate bearer recovery needs an explicit separate loader/activation slice, not relaxed enrollment validation.

Return ONLY device_id/request_id/csr_pem (the exact renewal request). Never return or log private key or operational token. No network calls. Generate a NEW RSA2048 key and signed SHA256 CSR once per enrollment generation; reuse exact persisted request and key after retries/restart. CSR CN device:<uuid>. Enrollment generation = SHA256 of ASCII operational_token, not current certificate serial (installation changes serial without changing generation). Bind persisted origin to exact validated base_url and immutable device_id.

Provisioned store_dir uses existing mqtt_credentials._open_directory ancestry policy. Open/create private rotation-state child (0700 runtime-owned, no access/default ACL); secure dirfd/no-follow traversal. Do not chmod/repair unsafe existing files or ancestor directories. Fixed private .lock file (0600, runtime-owned, ACL-free, regular file) with flock exclusive across readers/writers, including independent processes. No handler/concurrency-policy edits. Securely create new files with inherited ACL removal before publication. Existing insecure state fails closed.

Fixed pending.json exact keys: version literal integer 1 (not bool), base_url, device_id, generation_sha256 lowercase64hex, request_id canonical lowercaseUUID, private_key PKCS8 PEM, csr_pem PEM. No bearer token, current certificate or report state in this file. JSON bytes <=32768, regular runtime-owned0600 no ACL, no symlink/FIFO; strict fields/types and cryptographic CSR signature, CN and private-key public-key equality; key RSA>=2048. For SAME origin/device/generation return byte-identical request. Mismatched generation/origin/device, malformed or unsafe state raises sanitized EnrollmentError without replacement: administrator recovery/reenrollment handling is future work, never silently overwrite a pending private key. No automatic state deletion.

## Durable publication

Under lock, stage new private file in same private directory, write/flush/fsync, atomic replace to pending.json, fsync directory, then read back and validate before returning public request. Pre-replace failure preserves prior state and cleans staging. Post-replace directory fsync/readback failure raises, no request returned; subsequent retry validates/reuses whatever fully published state exists rather than issuing another key. Do not pretend rollback after atomic replace/fsync failure. Use safe fixed error text suppressing secret-bearing library values. Ensure descriptor/lock cleanup for exceptions. Tests must cover missing-parent/unsafe ancestry, private-mode/ACL/symlink/FIFO rejection, malformed/oversized/extra/type errors, key/CSR tamper, generation/origin/id mismatch, write/fsync/replace/readback failures, retry after post-replace failure, concurrent threads/processes and subprocess exit+restart retaining exact request. No insecure-host chmod to run tests.
