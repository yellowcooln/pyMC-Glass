## Atomic credential replacement

When current equals previous_bundle: stage candidate privately in existing credential parent, same private metadata/ACL policy; bound/writecheck/flush/fsync and full private readback+_validate_certificate+candidate equality BEFORE replace. Immediately reread current to compare against earlier snapshot (best-effort cooperating writer guard under fixed lock, not cross-process lock guarantee for administrators not using it); mismatch raises without replace. Atomic replace using dirfds, fsync credential parent, private readback+candidate equality/crypto after replace. Return only after all durability/readback checks. On pre-replace failure preserve old file byte-for-byte and cleanup staging. On post-replace failure raise sanitized error, do NOT pretend rollback; next retry detects candidate, fsyncs directory/revalidates and returns success without another rewrite. If current already candidate: validate journal/pending/current fully and fsync parent before returning; exact bytes remain unchanged.

Public receipt exact fields: device_id,request_id,cert_serial,fingerprint_sha256,expires_at,state='bundle_installed'. No key/token/PEM/filepath/backup. This means offline credential bundle installed/read back, NOT materialized MQTT credentials, callback success, delivery or broker proof. Old immutable MQTT materialization directories stay intact. Retirement and completed-generation state are explicitly NEXT slice before more than one renewal can occur; retained journal/pending bounds one uncertain in-flight rotation and avoids silently losing keys.
